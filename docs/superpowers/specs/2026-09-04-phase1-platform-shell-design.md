# 제주 재난 AX 플랫폼 — 1단계: 플랫폼 공통 셸 설계

## 배경

"1차년도 세부 수행계획"(저염분수·고수온 / 연안 안전관리 / 하천 범람 3개 실증 서비스 + AX 컨트롤타워)을 바탕으로
제작된 4개 유저플로우 와이어프레임(총 82개 화면·상태)을 프론트엔드 프로토타입으로 구현한다. 실제 백엔드/API
연동 없이 더미데이터로 동작하며, 목적은 화면 구조와 정보 구조(IA)를 검증하는 것이다.

Figma 원본("제주재난관리 플랫폼.fig")은 연결 계정의 편집 권한 부재로 접근하지 못했다. 대신 사용자가 제공한
4개 유저플로우 HTML(피그마 wireframe export)을 1차 자료로 사용했다.

## 범위 분해

82개 화면은 4개 플로우로 나뉘며, 다수는 독립 페이지가 아니라 동일 화면의 에러·빈·성공 상태(state)다.

| 플로우 파일 | 서비스 | 화면 수(상태 포함) | 단계 |
|---|---|---|---|
| 플랫폼_사용자_유저플로우.html | 플랫폼 공통 셸 (로그인·GIS 통합 대시보드·시스템 모니터링·이력) | 21 | **1단계 (본 문서)** |
| 저염분수_고수온_예측_시스템_플로우.html | 양식장 대응 | 31 | 2단계 |
| 연안_안전관리시스템_유저플로우.html | 연안 안전 | 17 | 3단계 |
| 하천_범람예측_경보_시스템_유저플로우.html | 하천 범람 | 13 | 4단계 |

1단계는 플랫폼 셸(로그인, 공통 레이아웃/내비게이션, GIS 통합 대시보드, 시스템 모니터링)만 구현하고,
나머지 3개 서비스는 진입 스텁 페이지로만 연결한다. 이후 단계에서 각 플로우를 순차적으로 구현한다.

## 기술 스택

- React 19 + TypeScript + Vite (SPA)
- Tailwind CSS v4 — `@theme`로 위험등급 시맨틱 토큰(danger/warning/caution/safe/info/offline) 정의
- react-router-dom — 클라이언트 라우팅 + 인증 가드(`RequireAuth`)
- recharts — 센서 시계열 차트
- 지도: 실제 GIS API 키 없이, 제주도 외곽선을 간략화한 커스텀 SVG + 위험 마커로 대체(`JejuRiskMap`)
- 인증: sessionStorage 기반 목업(`mockAuth`) — 실제 백엔드 없음. 기관ID `jeju-ax`(담당자) / `guest`(권한 제한) 두 데모 계정 제공

## 데이터

와이어프레임에 표기된 문구·수치(하천 범람 위험 "경계 2 / 주의 1", 연안 위험 "위험 3 / 감시 5" 등)를 그대로
더미데이터로 옮겨 `src/data/mockDashboard.ts`, `src/data/mockMonitoring.ts`에 정적으로 구성했다. 실시간 갱신은
없으며, 화면상 "갱신 시각"은 클라이언트 현재 시각을 표시한다.

## 화면 매핑 (1단계)

- 로그인 화면 → `LoginPage`
- 권한 오류 안내 화면 → `ForbiddenPage`
- GIS 통합 대시보드 → `DashboardPage`
- 시스템 모니터링 화면 → `MonitoringPage`
- 양식장 대응 / 연안 안전 / 하천 범람 / 이력·보고서 → `PlaceholderServicePage` (다음 단계 예고)

## 다음 단계

2~4단계는 각각 별도 설계 문서를 작성한 뒤 진행한다. 우선순위는 사용자 확인 후 결정.
