# 스테이징 하천 시나리오 화면 연결·지점 표시·메뉴 검토

작성: Codex / 2026-10-01

## 1. 문서 목적과 검토 범위

사용자는 스테이징에 하천범람 시나리오를 업로드하고, 종합상황·GIS 상황·하천 대시보드에서 수치와 위험등급을 확인하며 기존 대응 절차를 진행하려 한다. 다음 세 가지에 대한 검토 결과를 Claude에게 인계한다.

1. 종합상황·GIS 상황에서 하천 시나리오 데이터 정보가 확인되지 않는다.
2. 하천 보드 브리핑에 쇠소깍이 대표로 표시돼 돈내코가 정상이라 숨겨진 것인지, 오류인지 불명확하다.
3. 하천 메뉴를 대응 흐름 순으로 배치하고 시나리오 실행을 별도로 구분하고 싶다.

검토 기준은 `staging` 커밋 `47ab65f`이다. 원격 staging HEAD가 동일함을 확인했으며, 배포 주소는 https://jeju-disaster-platform-staging.vercel.app 이다.

코드와 배포 화면을 확인했다. 점검 브라우저에는 사용자의 업로드 실행 상태가 없었으므로, 사용자 이미지의 돈내코 입력값 자체나 해당 실행의 화면 전환은 재현하지 않았다. 아래에는 코드로 확인된 사실과 개선 제안을 구분해 기록한다.

이번 작업은 검토 문서 작성이다. 앱 기능 수정·커밋·푸시·배포는 수행하지 않았다. 이 문서 자체를 추가 구현·배포 승인으로 해석하지 않는다.

## 2. 종합상황·GIS 상황의 연결 누락

### 확인된 사실

- `src/pages/DashboardPage.tsx`는 이미 `useRiverRun()`을 구독한다. 따라서 단순히 구독 훅을 다시 추가하는 것으로 해결할 문제는 아니다.
- `src/data/riverRunState.ts`의 `projectToMock()`은 하천 지점의 등급, 서비스 카드 등급별 집계, 지도 마커의 `level`을 갱신한다.
- 같은 함수는 하천 전용 판단 근거·모의 영향·승인 이력·통제 이력 등을 갱신한다. 하천 전용 화면에서 읽는 값과 통합 화면에서 읽는 값이 다르다.
- 통합 화면의 `dashboardSensors`, `timeSeries`, `sixHourSeries`, `recentActions`에는 이 실행 데이터가 투영되지 않는다. 초기 빈 배열이 유지된다.
- 통합 화면의 `aiInsights`는 정적인 기능 설명이다. 현재 하천 Q%나 연관 모의 관측을 보여주지 않는다.
- 통합 타임라인·지역 사건 현황·대응팀은 `mockIncidents.ts`의 `disasterIncidents`·`disasterResponseTeams` 등을 읽는다. 하천 실행 이력·자원 요청과 연결돼 있지 않다.
- `src/components/ui/JejuTileMap.tsx`의 지도 팝업은 `marker.value`를 표시할 수 있지만, 하천 시나리오 투영은 마커의 등급만 갱신하고 Q% 값을 넣지 않는다.

결론: 서비스 카드 집계와 지도 등급은 연결돼 있지만, 통합 화면에서 시나리오의 수치·근거·시간·대응을 확인하는 연결은 미완성이다. 모든 데이터가 전혀 연결되지 않았다고 판단해서 기존 연결을 다시 만들 필요는 없다.

### 개선 권장사항

종합상황과 GIS 상황이 같은 하천 실행 상태에서 아래 값을 읽도록 연결한다. 기존 계산 함수와 구독을 재사용하고 화면별로 별도 모의값을 만들지 않는다.

| 표시 위치 | 연결할 내용 |
| --- | --- |
| 하천 시나리오 요약 | 실행 상태, 현재 시나리오 시각, 돈내코·쇠소깍의 Q%·적용 등급·관측시각 |
| GIS 마커 팝업 | 해당 지점 Q%, 적용 등급, 해당 지점의 마지막 관측시각, 시나리오 모의 표식 |
| 관측정보 | 두 지점의 Q% 입력값. 실측 센서 수위와 구분해서 표시 |
| 추이 그래프 | 현재 재생 시점까지의 돈내코·쇠소깍 Q% 시계열 |
| 판단 근거 | Q% 판정 근거와 기존 계산 함수가 생성한 모의 강우·강우대·토양 포화도 |
| 타임라인·최근 조치 | 실제 실행에서 발생한 관측 진행·등급 전환·승인·자원 상태 변경 이력 |
| 대응 현황 | 요청·승인·이동·도착·복귀 등 현재 가상 자원 상태와 모의 영향 구역·인원 |

주의할 설계 사항:

- Q%를 `돈내코수위`·`쇠소깍수위` 같은 실제 수위(m) 필드에 넣지 않는다. Q% 전용 그래프를 사용하고 `riverFlowRatioAnalysis()`를 재사용한다.
- 빈 실측 센서 목록을 채우는 대신, 시나리오 입력 관측으로 명확하게 표시한다. 수집상태 엑셀의 통신 상태와 재난 위험등급은 계속 분리한다.
- 모의 주변 관측은 `riverScenarioObservations.ts`의 기존 계산 결과를 재사용한다. 위험등급 입력은 계속 Q%이며, 주변 모의값으로 추가 승격하지 않는다.
- Q%가 높다는 이유만으로 실제 피해접수·기관 발송·기관 연결 완료를 만들어내지 않는다. 시나리오 활동 이력과 실제 피해접수는 의미가 다르다. 통합 타임라인에 시나리오 활동을 별도로 합치거나 전용 영역으로 표시하는 방식이 적절하다.
- 기존 통합 화면에는 실행 버전이 의존성에 없는 `useMemo`도 있다. 실행 데이터를 합쳐 넣을 때 필터 결과·유형 목록·날짜 범위가 열린 화면에서도 재계산되는지 확인한다.
- 새로고침·초기화·재업로드 시 이전 실행의 수치나 이력이 남지 않도록 한다. 다른 서비스의 데이터는 보존한다.

## 3. 돈내코 표시: 삭제·숨김이 아니라 대표 제목과 미입력 구분 문제

### 확인된 사실

- `mockRiver.ts`의 `riverStatuses`에는 쇠소깍과 돈내코가 모두 있다.
- `src/pages/domain/leaderBriefs.ts`의 `riverBrief()`는 두 지점을 위험등급 순으로 정렬해 가장 위험한 지점 하나를 브리핑 제목과 대표 배지에 사용한다.
- 브리핑 본문은 두 지점 모두를 표시한다. 사용자 이미지 1에도 돈내코의 `범람 도달 해당 없음` 문구가 있다.
- 정상 지점을 제외하는 필터는 없다. 배포된 상세 대시보드의 하천 위험 요약에서도 두 지점의 정상 카드가 모두 표시되는 것을 확인했다.
- 다만 `projectToMock()`은 지점 상태가 없으면 `safe`를 적용한다. `eta`도 실제 정상 관측과 미입력 모두 `해당 없음`으로 표시한다.
- `updatedAt`은 현재 재생 묶음의 시각으로 갱신한다. 그 묶음에 특정 지점의 새 관측이 없어도 해당 지점의 관측시각처럼 보일 수 있다.

따라서 이미지의 돈내코가 실제로 정상인지, 입력이 없어서 정상 기본값으로 보이는지는 사용자 시계열을 확인해야 한다. 대표 제목이 쇠소깍이라는 사실만으로 돈내코 누락 오류라고 판단하면 안 된다.

### 개선 권장사항

- 가장 위험한 지점을 대표 제목으로 쓰는 기존 요약은 유지할 수 있다.
- 그 아래에 두 지점의 독립 요약을 항상 표시한다: `돈내코 12% · 정상 · 관측 11:45`, `쇠소깍 58% · 주의 · 관측 11:45` 등.
- 관측이 없는 지점은 `관측값 없음` 또는 `시나리오 미입력`으로 표시한다. 정상 관측이 확보됐다는 의미로 안내하지 않는다.
- 지점별 마지막 관측시각은 `riverFlowRatioAnalysis(run).latest[location]` 등 지점별 관측 결과를 사용한다. 현재 시나리오 시각과 구분한다.
- 결측 시 직전 값 유지와 하향 유지 30분 규칙은 그대로 유지한다. 현재 Q%와 적용 등급이 다른 경우에는 하향 유지 중임을 설명한다.

## 4. 메뉴 순서와 시나리오 실행 분리

### 현재 구조

메뉴의 단일 기준은 `src/pages/river/riverNav.ts`의 `RIVER_NAV`이다. 보드 메뉴와 상세 화면 사이드바가 이 목록을 공유한다.

현재 상세 사이드바 순서:

`상세 대시보드 → 시나리오 실행 → 데이터 수집 → 상황 분석 → 경보 발송 → 현장 통제 → 출동 요청 → 종료 보고`

### 권장 구조

사용자가 제안한 대응 중심 순서를 반영하되, 기존 종료 보고 접근을 유지한다.

1. 상세 대시보드
2. 상황 분석
3. 경보 발송
4. 출동 요청
5. 현장 통제
6. 종료 보고
7. 데이터 수집

구분선 또는 별도 그룹 제목 아래:

- 시나리오 실행

상황 파악 → 판단 → 경보 → 출동·통제 → 종료의 흐름을 먼저 보여주고, 데이터 확인과 시나리오 설정을 후순위로 배치한다. 출동과 현장 통제는 실제 상황에서 병행할 수 있으므로 메뉴 순서를 강제 실행 순서로 구현하지 않는다.

구현 시 `RIVER_NAV`의 순서를 기준으로 보드·사이드바를 함께 맞춘다. 별도 그룹을 표현하려면 공통 내비게이션 타입·렌더러에 최소한의 그룹 정보를 추가한다. 다른 서비스의 메뉴 순서는 이 하천 검토를 근거로 일괄 변경하지 않는다. 활성 메뉴·상세 링크·기존 라우트도 유지한다.

## 5. 완료 확인 기준

아래는 후속 구현 시 권장하는 검증 기준이다. 이번 문서 작성에서 통과를 확인했다는 의미는 아니다.

1. 같은 브라우저·같은 스테이징 주소에서 시나리오를 실행하고, 종합상황·GIS 상황·하천 보드·상세 대시보드를 열어 둔다.
2. 돈내코 정상/쇠소깍 주의, 돈내코 경계/쇠소깍 관심, 두 지점 정상 조합에서 각 지점 Q%·등급·관측시각이 일치한다.
3. 돈내코 행이 없는 입력에서는 돈내코가 `관측값 없음`으로 표시된다. 두 지점 관측 간격이 다르면 각 지점의 마지막 관측시각이 유지된다.
4. 다음 시점 진행과 자동 재생 시 열린 통합 화면의 관측값·그래프·마커·집계가 즉시 갱신된다. 미래 입력값은 미리 표시하지 않는다.
5. 경보 승인·출동 요청·자원 승인·도착·복귀를 기존 상세 화면에서 처리하면 통합 대응 현황과 이력에도 같은 상태가 반영된다.
6. 초기화·동일 파일 재업로드·강제 종료 뒤 재시작 시 이전 실행 정보가 남지 않는다.
7. Q%는 % 단위, 강우는 mm/h 등 기존 단위로 표시하고 모의 출처를 명시한다. 실제 수위(m)나 실측 센서값으로 오인할 표현이 없다.
8. 보드와 상세 사이드바의 메뉴 순서가 일치하고, 시나리오 실행이 별도 구역으로 구분되며 종료 보고도 접근 가능하다.
9. `npm run build:staging`, `npm run lint`, 관련 테스트를 확인하고, 실행 중 `window.__jejuConsistency()`의 어긋남이 없는지 확인한다. 기존 일치 검사는 모든 통합 연결 누락을 잡지는 못하므로 위 화면 확인도 함께 수행한다.

현재 실행은 브라우저 저장소 기반이다. 다른 PC·브라우저·시크릿 창이나 로컬 주소에는 자동 공유되지 않으므로, 검증은 같은 스테이징 origin에서 진행한다.
