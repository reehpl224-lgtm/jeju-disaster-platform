# 스테이징 하천 시나리오 더미데이터 구성안 (2026-09-30)

## 1. 목적

스테이징에서 하천범람 시나리오를 `정상 → 관심 → 주의 → 경계 → 심각 → 단계별 하향 → 정상 종료`까지 한 번에 검증한다.

사용자가 엑셀에 넣는 변화값은 **지점별 관측시각과 계획홍수량비율(%)**뿐이다. 나머지는 플랫폼이 고정 카탈로그 또는 위험등급 파생값으로 제공한다.

샘플 업로드 파일:

- `outputs/01a0eb63-d9d6-7122-aaa7-fdce4ca32193/하천_스테이징_시나리오_전체흐름_샘플.xlsx`

## 2. 데이터 책임 분리

| 구분 | 데이터 | 처리 방식 |
|---|---|---|
| 사용자 입력 | 지점, 관측시각, 계획홍수량비율(%) | 엑셀 업로드 |
| 위험등급 | 정상·관심·주의·경계·심각 | 계획홍수량비율로 계산 |
| 자동 파생 | 영향시설 수, 영향인원, 단계별 상황 문구 | 지점+위험등급 규칙으로 계산 |
| 고정 모의 카탈로그 | 시설명, 대응인력·통제게이트·차량의 가용 목록 | 코드의 기준 데이터로 제공 |
| 사용자 대응 행위 | 경보 승인, 출동 승인, 자원 요청·승인, 복귀, 종료 확인 | 화면에서 담당자가 수행하고 이력 저장 |

출동 자원을 위험등급만으로 곧바로 배치 완료 처리하지 않는다. 단계별 권장 자원과 가용 목록은 자동 제시하되 요청·승인 과정은 사용자가 수행해야 실제 대응 플로우를 검증할 수 있다.

### 입력 항목 최종 확정

`시간별입력` 시트는 현재의 세 열을 그대로 유지한다.

| 필수 열 | 단위 | 용도 |
|---|---|---|
| 지점 | 코드/명칭 | 돈내코·쇠소깍 구분 |
| 관측시각 | `YYYY-MM-DD HH:mm` | 시나리오 재생 순서와 유지시간 계산 |
| 계획홍수량비율(%) | % | 위험등급을 결정하는 유일한 입력값 |

강우량, 수위(m), 유속, 레이더, CCTV, 영향시설, 영향인원, 자원 수량은 엑셀 필수 열로 추가하지 않는다. 모든 값을 사용자에게 입력시키면 같은 시나리오에서 서로 모순되는 값이 생기고 재현성이 떨어진다.

### 수위와 계획홍수량비율 구분

화면의 수위 센서 `1.05 m`, `0.98 m` 같은 값은 물의 높이이고 계획홍수량비율(%)이 아니다. 수위에서 Q%를 계산하려면 지점별 수위-유량 관계식과 계획홍수량 기준이 필요하므로, 근거가 없는 상태에서 서로 변환하지 않는다.

- 위험등급 판단: 업로드한 계획홍수량비율(%)만 사용
- 실측 센서 수위(m)·수집상태: 별도 수집상태 데이터로 유지
- 스테이징 화면에 변화하는 수위가 꼭 필요할 때: `모의 수위`로 명시하고 시나리오 내부의 고정 시계열을 사용한다. Q%에서 실제 수위로 환산한 것처럼 표시하지 않는다.
- 강우·레이더·CCTV: 위험등급의 필수 입력이 아닌 보조 상황 데이터로 자동 생성하고 `모의` 출처를 표시한다.

따라서 데이터 수집 현황의 모든 항목이 채워지지 않아도 시나리오는 실행할 수 있다. 수집 데이터가 비어 있거나 오류여도 위험등급을 임의로 올리지 않으며, 수집상태와 재난 위험등급은 계속 분리한다.

## 3. 등급·영향 규칙

| 계획홍수량비율 | 위험등급 | 영향시설 | 영향인원 | 권장 자원(모의) |

- 돈내코: `D-01 모의 하천변 산책구역`, `D-02 모의 하상 접근로`, `D-03 모의 임시주차구역`
- 쇠소깍: `S-01 모의 하구 산책구역`, `S-02 모의 하상 접근로`, `S-03 모의 저지대 대기구역`

## 5. 현재 구현 상태

- 동일 `observedAt`의 돈내코·쇠소깍 행 묶음 처리는 구현·테스트 완료됐다.
- 단계별 모의 영향시설·영향인원은 대시보드·상황분석·브리핑에 투영된다.
- 자원은 `권장/가용 자원 표시 → 담당자 요청 → 승인 → 모의 출동 → 도착 → 복귀` 순서로 유지한다.
- 스테이징에서는 동네예보만 실호출하고 다른 외부 API는 실호출을 차단한다.

## 6. 완료 기준

- 샘플 엑셀 업로드가 오류 없이 28행을 읽는다.
- `다음 시점` 1회당 동일 관측시각의 두 지점이 동시에 바뀐다.
- 카드, 지도 마커, 상황분석, 팀장 브리핑의 등급·영향값이 서로 일치한다.
- 상향은 즉시, 하향은 30분 유지 후 한 단계씩 적용된다.
- 경보 승인과 자원 요청·승인·도착·복귀 이력이 시나리오 시각으로 남는다.
- 정상 단계와 자원 복귀 조건 충족 뒤 정상 종료가 가능하다.
- 초기화 또는 같은 파일 재업로드 후 새 `runId`로 처음부터 다시 실행할 수 있다.

## 7. 추가 수정 요청 — 자동 재생·타임라인·모의 실시간 연동

### 7-1. 확인된 현재 동작

1. 엑셀 파일을 고르면 검증 결과만 `pending`에 저장된다.
2. `이 시나리오로 시작`을 눌러야 새 실행이 만들어지며, 이때도 `playheadIndex=-1`, `playing=false`라 첫 시점은 아직 적용되지 않는다.
3. `자동 재생` 버튼은 `playing` 값만 토글한다. 이를 읽어 `advance()`를 호출하는 타이머가 없어 실제 자동 재생은 되지 않는다.
4. `다음 시점`은 정상 동작하며 같은 관측시각의 두 지점을 한 묶음으로 반영한다.
5. 우측 `타임라인`은 `riverControlTimeline`만 표시한다. Q% 관측·등급 변화는 실행 이력에 넣지 않기 때문에 승인·자원 조작 전에는 빈 화면이 된다.
6. 스테이징 `실시간 우량 관측`은 `MOCK_STATIONS`의 시각·강우·기온·습도·풍속이 모두 빈 값/null이라 `-`만 표시된다.
7. `RainfallObservationPanel`은 마운트 시 한 번만 조회하므로, 모의값을 실행 상태에서 계산하더라도 현재 구조로는 다음 시점 진행 때 다시 읽지 않는다.

### 7-2. 자동 재생 요구사항

- 업로드 즉시 무조건 실행하지 않는다. `검증 완료 → 이 시나리오로 시작`이라는 명시적 사용자 확인 단계는 유지한다.
- 시작 시 첫 관측시각 묶음을 즉시 한 번 적용한다.
- `자동 재생`을 누르면 기본 **5초마다 관측시각 묶음 1개**를 `advance()`한다. 이는 화면 재생 속도이며 엑셀의 시나리오 시각 간격과 별개다.
- `일시정지`, 마지막 시점, 정상/강제 종료 시 타이머를 반드시 정리하고 `playing=false`로 만든다.
- 경계·심각 최초 진입 또는 경보/출동 승인 대기 시 자동 일시정지를 권장한다. 사용자가 대응 화면을 확인한 뒤 다시 재생할 수 있어야 한다.
- 타이머 중복 생성, 화면 이동 후 잔존, 새 파일 재업로드 후 이전 타이머 재개가 없어야 한다.

### 7-3. 시나리오 시각 간격

- 파서는 15분 고정이 아니며 `YYYY-MM-DD HH:mm` 형식의 임의 간격을 허용한다.
- 1차년도 시연 기본값은 **15분 간격**을 권장한다. 모의 자원 도착 15분과 하향 유지 30분을 정확히 검증하기 쉽다.
- 급격한 상승을 자세히 보여줄 필요가 있는 구간만 5~10분 관측을 추가할 수 있다.
- 현재 전체 흐름 샘플은 상승 구간 10분, 하향 확인 구간 30분이다. 동작에는 문제가 없지만 15분 도착 사건은 다음 관측인 20분 뒤에 표시될 수 있다. 정확한 시각 시연이 필요하면 샘플을 15분 기준으로 재작성한다.
- UI의 `N개 시점`, `시점 x/y`는 행 수가 아니라 중복을 제거한 `observedAt` 묶음 수로 표시한다.

### 7-4. 우측 타임라인 연결

`advance()`가 관측시각 묶음을 처리할 때 실행 이력에 한 건을 추가한다.

- 표시 내용: 시나리오 시각, 돈내코 Q%·등급, 쇠소깍 Q%·등급
- 단계가 바뀌면 `정상→관심`, `경계→심각`, `심각→경계`처럼 변경 전후를 함께 기록
- 하향 유지시간 미충족이면 `하향 대기 시작`을 중복 없이 기록
- 기존 경보 승인·출동 승인·자원 요청·도착·복귀·종료 이력은 그대로 함께 표시
- 빈 배열이면 빈 화면 대신 `시나리오를 시작하고 첫 시점을 진행하면 표시됩니다.` 안내 표시

같은 렌더링에서 이력이 중복 추가되지 않도록 이력 생성은 `projectToMock()`이 아니라 상태 명령인 `loadTimeline()`·`advance()` 안에서만 수행한다.

### 7-5. 스테이징 모의 우량·기상값 연결

엑셀 입력 열은 현재 3개를 유지한다. Q%를 강우량(mm)이나 수위(m)로 실제 환산한 것처럼 처리하지 않는다.

- 스테이징 전용 모의 상황 데이터는 현재 시나리오 시각/진행 단계에 따라 결정적으로 생성한다.
- 우량·기온·습도·풍속·관측시각을 비어 있지 않은 값으로 제공하고 `모의(스테이징)` 표식을 유지한다.
- 위험 단계가 올라갈 때 강우 강도가 증가하고 하향 구간에서는 감소하도록 하되, 일누적 강우는 감소하지 않게 한다.
- 같은 파일을 재업로드하면 같은 모의값 순서를 재현해야 한다. 임의 난수는 사용하지 않는다.
- `RainfallObservationPanel`은 `useRiverRun().version`을 구독하거나 시나리오 컨텍스트를 prop으로 받아 시점 변경 때 다시 계산한다.
- 기상청 단기예보는 실제 API 참고값으로 유지하며 시나리오 모의값으로 덮어쓰지 않는다.
- 실제 단기예보와 모의 우량이 다를 수 있으므로 `실제 예보 참고값`과 `시나리오 모의 관측`을 화면에서 명확히 구분한다.

2026-10-01 구현 보완:

- `riverScenarioObservations.ts`가 현재 재생 시점의 Q% 묶음으로 모의 시간당·일누적 강우, 강우대, 유역 포화도, Q% 추세를 한 번만 계산한다. 일누적 강우는 15분으로 고정하지 않고 엑셀 관측시각의 실제 간격(10·15·30분 등)을 적분한다.
- `rainfallApi.ts`의 스테이징 우량 패널과 `riverRunState.projectToMock()`의 팀장 브리핑·상황분석 카드가 이 계산 결과를 공유한다.
- 수위 카드는 실제 m를 만들지 않고 `수위 지표(Q%)`로 표시한다. 실제 수위 센서·수위×조위 차트·센서 교차검증은 계속 별도 데이터로 남긴다.
- 모의 강우·레이더·토양 포화도는 상황 설명용이며 위험등급을 다시 판정하지 않는다. 위험등급의 유일한 입력은 업로드한 Q%다.
- 토양 포화도는 별도 배수·건조 모형이 없는 1차년도 시연 범위에서 같은 실행 중 감소하지 않도록 누적한다.

### 7-6. 추가 완료 기준

- 업로드만 했을 때는 재생되지 않고, `이 시나리오로 시작` 후 첫 시점이 적용된다.
- 자동 재생 시 5초마다 동일 관측시각 묶음이 한 번씩 적용된다.
- 일시정지 후 10초 이상 기다려도 시점이 이동하지 않는다.
- 경계·심각 또는 승인 대기 자동 정지 정책을 적용했다면 해당 조건에서 멈춘다.
- 타임라인에 각 Q% 관측 묶음과 위험등급 변화가 시나리오 시각 순서로 나타난다.
- 스테이징 우량 패널의 `-`가 모의값으로 바뀌고 시점 진행에 따라 갱신된다.
- 일누적 강우는 시나리오 진행 중 감소하지 않는다.
- 동네예보는 계속 실제 API 값과 `실시간` 표식을 사용한다.
- `npm run build`, `npm run build:staging`, `npm run lint`, `node --test tests/*.test.mjs`가 통과한다.
- 브라우저에서 샘플 업로드→시작→자동 재생→자동 정지/일시정지→승인·자원 배치→복귀→종료까지 확인한다.
