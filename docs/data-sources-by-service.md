# 서비스별 데이터 현황 (2026-09-28 기준)

> 이 문서는 제주 재난 AX 플랫폼(6개 서비스: 호우·태풍·폭염·하천범람·저염분 고수온·연안 안전관리)에서
> 실제로 코드에 반영된 데이터 출처를 아래 4가지 기준으로 정리한 것입니다.
>
> 1. **현재 사용 가능한 데이터** — 화면에 실제로 연동돼 있는 데이터(실시간 API, 실측 스냅샷 등)
> 2. **제주 레거시 데이터** — 현재는 화면에 적용되지 않았지만, 도·행정시가 이미 보유해 적용이 가능한 데이터
> 3. **요청 가능한 데이터** — 3대 실증서비스(하천·아쿠아·연안) 실증사 컨소시엄으로부터 받을 수 있는 데이터
> 4. **현재 없는 데이터** — 필요하지만 현재는 구할 방법이 없는 데이터
>
> 근거 자료: 실증 3사 착수보고 발표자료(소다시스템·지오시스템리서치·올포랜드), 착수보고회 회의록,
> 현업요구사항 정리·레거시시스템 현황 조사 면담 결과서, "1차년도(2026년) 사용 가능 레거시 데이터
> 현황 및 연계 분석" 문서(제주TP), `AGENTS.md` 및 `src/data/mockPilotStatus.ts`.
>
> 하천·아쿠아·연안 3개 서비스는 실증 3사가 있어 "요청 가능한 데이터" 항목이 존재하지만, 호우·태풍·
> 폭염 3개 서비스는 새 AI 예측을 만드는 서비스가 아니라 레거시 연계·공공정보 안내 성격이라 전담
> 실증사가 없고, 따라서 "요청 가능한 데이터" 항목이 원천적으로 없습니다.

(`src/data/mockPilotStatus.ts`)에 이 4단계 분류(`live-api`/`legacy`/`partner`+`new-infra`/`dummy`
태그)가 구조화돼 있어 `/pilot-status` 화면에서도 같은 내용을 확인할 수 있습니다. 호우·태풍·폭염
3개는 이런 전담 실증사가 없는 구조라 "요청 가능한 데이터" 항목이 원천적으로 없다는 점이 3대
서비스와의 핵심 차이입니다.

이 문서는 2026-09-28 시점 코드·문서 상태를 기준으로 작성되었습니다. 실증사와의 협의가 진행되거나
새 레거시 데이터 문서가 확인되면 이 표도 함께 갱신해야 합니다.

## 실제 데이터 연동 진행 이력 (2026-09-28)

이 문서 작성 후, 실제로 연동 가능한 항목을 난이도순(Tier 1~4)으로 정리해 순서대로 진행했습니다.

- **Tier 1(즉시 가능, 완료)**: 연안 실시간 해양관측 패널을 제주 전역 8개 지점 대신 함덕(김녕
  인근)·협재(정확 일치) 지점만 필터링하도록 개선. 새 API 신청·기관 협의 없이 이미 받아오던
  데이터를 이름으로 필터링만 한 것.
- **Tier 2(단기 가능, 부분 완료)**: 하천 우량 관측 패널(서귀포·제주남원 참고지점)에 이미 API
  응답에 포함돼 있었지만 버려지고 있던 10분 평균 풍속·풍향 필드를 추가로 노출. 같은 Tier의
  나머지 항목(레거시 시스템 API 프로토콜 협의, 도 CCTV 스트리밍 URL 협의)은 관리업체·통합관제
  센터와의 실제 협의가 선행돼야 하는 일이라 코딩 세션 범위 밖으로 남겨둠.
- **성산 풍속풍향계 실측 연동(보류)**: 실제 AWS 지점번호를 확인해야 하는데, 이 작업 환경의
  네트워크 정책이 `kma.go.kr` 계열 도메인을 전부 차단하고 있어 조회 불가. 사용자가 세션 환경
  설정에서 해당 도메인을 허용 목록에 추가하지 못해 보류 확정. 지어낸 지점번호로 대체하지 않음.
- **적설(눈) 실측 연동(불가로 확인)**: 방재기상관측(AWS) 매분자료 API 자체에 적설(SD) 필드가
  없어(2026-09-09 실측 검증된 컬럼 목록에 없음) 이 경로로는 연동 자체가 불가능함을 확인.
- **Tier 3(정식 기관 협의 필요, 착수 안 함)**: 제주시 하천 유속측정계·서귀포시 자동 우량 경보의
  도청 직접 연계, 소방안전본부·민방위경보시스템 연계 등은 전부 부서·기관 간 정식 협의가 필요한
  항목이라 이 세션에서는 진행하지 않기로 함(2026-09-28 사용자 결정). 실제 협의가 시작되면 이
  문서의 "② 제주 레거시" 항목들을 "① 현재 사용 가능"으로 옮기는 작업이 필요합니다.
